# Milestone 5 — Continuous expression

Polyphonic trigger pressure, pitch bend, and timbre now run in a dedicated Core `ExpressionEngine`.
Core still references no Avalonia, SDL, or Windows MIDI packages. No dependencies were added.
Your updated left-stick Left/Up momentary octaves and LB/RB held flat/sharp mappings are preserved.

## Default controls

| Control | Destination / behavior |
| --- | --- |
| Left Trigger / L2 | Polyphonic Key Pressure for the latest active D-pad note |
| Right Trigger / R2 | Polyphonic Key Pressure for the latest active face note |
| Right stick X | MIDI 1 pitch bend: Left 0, center 8192, Right 16383 |
| Right stick Y | CC74: Up 127, center 64, Down 0 |

Trigger pressure is 0..127. Each group's latest held note is selected independently; releasing it
falls back to the newest remaining held note in that group. Releasing the final note clears that
group's expression destination. A trigger without an active note updates state but emits no MIDI.
Pressing a note while its trigger is held applies the current pressure immediately after Note On.
Pressure always uses the held record's exact pitch/channel, including octave/accidental shifts and
optional last-note retuning. Moving selection clears the old pitch's pressure even if it still sounds.

MIDI 1 cannot give different pressures to owners sharing one channel/pitch. If both groups select
that same identity, the latest physical note press controls its pressure; the other lane remains
available for fallback. Shared notes retain the existing coalesced Note On/Off ownership.

The synth must support/respond to polyphonic aftertouch, pitch bend, and the selected CC to hear
them. MIDI pitch bend encodes a normalized position; its audible semitone range is set by the synth.
This milestone does not send pitch-bend-range RPN messages or implement channel/MPE trigger modes.

## Configurable response

`InstrumentConfiguration.Expression` contains independent D-pad/face aftertouch, pitch-bend, and
timbre configurations. `MidiInstrument.UpdateConfiguration` applies settings through Core.
The editing UI is implemented in [Milestone 6](MILESTONE-6.md); JSON profile persistence is implemented
in [Milestone 7](MILESTONE-7.md). The validation below records the Milestone 5 implementation.

- Trigger sources can be swapped between LeftTrigger/RightTrigger; each lane can be disabled.
  Default dead zone **0.05** and minimum threshold **0.02** after dead-zone removal. Values above
  the threshold rescale to full range before the curve. Neutral/release always returns to zero.
- Stick sources can use any normalized stick axis; each destination can be disabled. Default
  dead zone **0.08**, sensitivity **1**, X normal and Y inverted (Up increases timbre).
  Signed values outside the dead zone rescale to -1..1, then apply the curve and sensitivity.
- Curves: Linear, Quadratic, SquareRoot. Sensitivity multiplies the curved magnitude and saturates
  at 1. Smoothing is an optional exponential filter whose time constant is configurable in
  milliseconds; default **0**, valid 0..5000. Elapsed time, rather than event count, drives it.
- MIDI update rate defaults to **60 Hz** per channel/controller or channel/note destination.
  Valid 0..1000 Hz; **0 disables rate limiting**. Identical quantized values are always suppressed.
  The latest deferred value is retained and sent on a heartbeat without needing more axis events.
- Timbre CC defaults to **74**, configurable **0..119**. CC120..127 are channel-mode commands and
  cannot be used as continuous timbre. Neutral is 64 for every timbre CC.
- Returning to a dead zone snaps to exact pitch-bend 8192, timbre 64, or pressure 0, bypassing
  smoothing/rate limiting. Selection/fallback changes apply pressure immediately.

Example programmatic configuration:

```csharp
var settings = instrument.CaptureSnapshot().Configuration;
instrument.UpdateConfiguration(settings with
{
    Expression = settings.Expression with
    {
        PitchBend = settings.Expression.PitchBend with
        {
            Response = settings.Expression.PitchBend.Response with
            {
                DeadZone = 0.12f,
                Curve = ResponseCurve.Quadratic,
                SmoothingMilliseconds = 15,
                UpdateRateHz = 100
            }
        },
        Timbre = settings.Expression.Timbre with { ControllerNumber = 11 }
    }
});
```

## State, scheduling, and safety

`MusicalStateSnapshot.Expression` exposes processed D-pad/face pressure, pitch bend, and timbre.
The GUI samples these at 30 Hz; the MIDI activity monitor shows events actually generated by Core.
The processed readout may briefly lead MIDI when a non-neutral value is rate limited.

`MappingEngine` accepts an optional `TimeProvider` for deterministic hardware-free tests. A selected
SDL controller's owner loop emits `GamepadEventKind.Tick` after each bounded event batch (normally
about every 4 ms at idle). Heartbeats do not increment the raw input counter or pass through UI.
Other input implementations must supply ticks while smoothing or deferred expression is pending.
Transforms, smoothers, and destination ledgers use fixed-size storage and allocate no objects per
input/tick. No file I/O or Avalonia work occurs in expression processing.

Panic, switching outputs/controllers, disconnect, shutdown, and fatal input errors clear pressure,
restore touched timbre destinations to 64, center touched pitch-bend channels, and stop tracked notes.
Deferred values/filter state clear so they cannot replay after cleanup. Changing expression sources,
CCs, or MIDI channel restores old destinations first without releasing held notes; held-note
pressure retains each record's original channel, while channel-wide expression uses the new channel.
The backend also tracks pressure and optional CC reset metadata for messages actually sent, covering
queue/send failure cleanup independently of Core. Removed destinations cannot receive cleanup;
local state clears and stale messages are not replayed after an explicit reconnect.

## Build and validation

Use the SDK setup in [README](../README.md), then:

```powershell
dotnet build PadToMIDI.sln -c Release
dotnet test --project tests/PadToMIDI.Core.Tests -c Release --no-build --no-restore
dotnet test --project tests/PadToMIDI.Midi.Windows.Tests -c Release --no-build --no-restore
dotnet run --project tools/PadToMIDI.InputProbe -c Release
dotnet run --project tools/PadToMIDI.MidiProbe -c Release -- --synth-test
dotnet run --project src/PadToMIDI.App -c Release --no-build --no-restore
```

Validated in this workspace:

- **182 Core + 18 MIDI encoding tests = 200 passing tests**. New cases cover selection/fallback,
  pressure curves/thresholds/smoothing, held identity, shared pitches, deduplication, rates,
  deferred final values, bend/CC boundaries, source/inversion/sensitivity configuration, exact
  center, disabled modes, lifecycle/configuration cleanup, and callback failures.
- The deterministic **10,000-step** mixed configuration/modifier stress test now includes triggers,
  continuous stick values, heartbeats, pressure ownership, and expression bounds.
- Native SDL virtual-controller probe verifies L2/R2 poly pressure, full bend/center, CC74,
  heartbeat flushing, the current octave/accidental defaults, and hot-plug cleanup.
- Real Windows MIDI Services loopback compares the entire expression UMP sequence, including
  selection/fallback and Panic. Direct backend submission verifies note/pressure/custom-CC reset
  ledgers, followed by endpoint removal. The development synth bridge now forwards poly pressure.
- Avalonia live fixture verifies expression targets/values and shutdown cleanup. Debug/Release
  builds and the published app startup smoke test pass.

The existing `artifacts/current-publish` directory is refreshed with Milestone 5 so the previous
launch command still works. The Windows 11 25H2+ preview SDK requirement remains unchanged.
Physical controller/DAW compatibility and audible expression on your synth remain manual checks.
